# Prime on EVM

There is a separate Prime app for EVM chains at
[beta-evm.untangled.finance](https://beta-evm.untangled.finance). It runs on the
Base Sepolia test network and is built on different contracts from the Stellar
version. The table at the end lists the differences.

## The account

On EVM a Prime Account is a Safe with a Zodiac Roles module attached as its
execution contract. Every agent move goes through that module, and it refuses
anything outside the move's permission.

The account holds no funds and needs no allowance. The funds stay at your custody
address and only move from there, through a custody gate, to a venue and back. A
lending position belongs to custody, not to the Prime Account.

## Connecting and creating an account

Select **Connect a wallet** and choose MetaMask, Coinbase Wallet, Rabby or Trust
Wallet, or pair a phone wallet with WalletConnect. The wallet has to be on Base
Sepolia.

Go to **Accounts** and select **Create a Prime Account**. The steps are the same
as on Stellar: Account, Add signers, Approvals and Review. At the end you sign a
message and send one transaction, paid in ETH, which creates the Safe and its
execution contract. Your wallet becomes the first signer.

![The Accounts page with a Prime Account open](/img/prime/evm-accounts.png)

Each account on the Accounts page has two buttons when you expand it.

**Manage execution** shows the execution contract and whether it is live.
**Switch off** stops every agent at once, and **Create execution contract** turns
it back on. Both are changes to the account, so on a shared account you sign
first and the others finish from a link.

**Manage allowance** checks whether your wallet has given the account an
allowance for an asset (test USDC unless you enter another). The account never
needs one. If it finds one, **Revoke** sets it to zero.

![Manage execution on Base Sepolia](/img/prime/evm-manage-execution.png)

## Signers

Signers are on the **Signers** tab, as on Stellar, but you change one signer at a
time, and each change is one transaction. If the account needs more than one
approval, the change waits in the Queue for the others.

## Policies

**Custody-funded action** is the only policy available on EVM. **Spending limit**
and **Add a custom policy** would spend the account's own balance, and an EVM
Prime Account has none. Aave supply and withdraw are options inside the
custody-funded action.

![The Policies tab on EVM](/img/prime/evm-policies.png)

## Setting up a custody gate

The custody address, for example your MPC vault, keeps the funds. It sets up a
custody gate: a small Safe that only custody owns, with rules that let one Prime
Account ask it to draw from custody. The gate can only draw what custody allows,
can only use Aave v3 and Uniswap v3, and pays everything back to custody. Prime
doesn't own the gate.

Your MPC provider's approval rules set who signs for custody, and Prime
doesn't see them. The agent's limits are checked on chain by the Roles module.

Connect the custody wallet, go to **Accounts**, and under **Custody** select **Set
up a custody gate**. There are four steps.

1. The Custody step uses the connected wallet as the custody address.
2. In Destinations, enter the Prime Account the gate serves. Only that account
   can call the gate. The venues are fixed: the Aave v3 pool for supplying and
   withdrawing USDC, and the Uniswap v3 router for swapping USDC to WETH.
   Whatever they return goes to the custody address.
3. In Limit, set an amount and an expiry in days for USDC and for aUSDC (the
   Aave position, which the gate draws when withdrawing). **Unlimited** means no
   cap and **Max** means no expiry.
4. Review shows the gate, where it draws from, where it can send funds, who can
   call it and the limits.

Custody signs a message and then sends five transactions: **Create the
gate**, **Approve USDC for Permit2**, **Allow the gate to draw USDC**, **Approve
aUSDC for Permit2** and **Allow the gate to draw aUSDC**. The page checks each one
on chain before offering the next. The allowances sit in Permit2, a standard
allowance contract, and custody can lower or revoke them at any time.

When all five are done, select **Open custody view**. It shows what the custody
address holds (USDC, aUSDC in Aave, and WETH) and each allowance to the gate.
Custody can get back to this view from any browser: on **Accounts**, under
**Custody**, each gate it owns has an **Open custody view** button.

![The custody view](/img/prime/evm-custody-view.png)

## Giving an agent a permission

After custody has set up the gate, a signer of the Prime Account goes to
**Policies** and selects **Custody-funded action**. The dialog finds the gate the
account already uses, or one set up for it in this browser. Otherwise paste the
gate's address and the app checks on chain that it serves this account. The
dialog shows the custody address and custody's allowances.

Each permission covers one band:

- What it may do: **Supply to Aave**, **Withdraw from Aave**, or a Uniswap swap
  from USDC to WETH.
- The amount band, from the first amount up to but not including the second.
- Who may act: either an agent key, which acts alone, or a shared account, which
  acts only once its own approval count is met. A shared account is a Prime
  Account too, for example the agent and an admin at 2 of 2, made with
  **Create a Prime Account**.

A permission names one address, so for a band that needs two people, name a
shared account with both of them as owners. Installing a permission changes the Prime
Account, so it may need the other signers.

![The permission dialog on EVM](/img/prime/evm-band-dialog.png)

Opening a permission on **Policies** shows what it allows, which gate it goes
through, the amount band, who may act, and that it never expires. It stays until
a signer removes it with **Revoke rule**, which also needs the account's approval
count.

![A swap permission's details](/img/prime/evm-rule-detail.png)

## Running a move

**Prime Execution**, under **Apps**, runs up to two calls in one transaction
through the execution contract.

1. Under **Authorised by**, pick the permission.
2. Fill in **Call 1**: supply, withdraw or swap, and the amount. For a swap,
   **Use live quote** sets the minimum to 1% below the current quote.
3. Select **Execute**. The app checks the call against the permission first. A
   move above the band, or one that custody's allowance no longer covers
   (revoked, expired or too small), stops here with nothing signed, and the app
   shows the reason.
4. Read **Review before you sign** and select **Run**. If the band belongs to a
   shared account the button says **Sign and queue**, and the other owners
   approve from the Queue (with that account selected) or from the co-sign link.

An agent that isn't a signer of the Prime Account adds it once with the **Prime
Account** button, using **Connect Safe smart account**.

![Prime Execution on EVM](/img/prime/evm-prime-execution.png)

## Transactions and co-signing

**Transactions** has a Queue and a History, as on Stellar. A queued item spells
out what will happen under **It runs, in order**. For a supply, that reads: the
gate draws 150 USDC from custody through its Permit2 allowance, approves the Aave
pool for 150 USDC, then supplies 150 USDC to Aave for custody. Select **Approve** to review it
and **Confirm** to sign. Once all approvals are in, any owner can submit it with
**Execute Safe transaction** or **Sign and submit**.

## Connected apps

You can pair an app with the Prime Account over WalletConnect, but on EVM it can
only ask for message signatures, such as a sign-in or an off-chain order. If it
asks to send a transaction, the app shows the request and declines it.

**Safe sign-in**, under **Apps**, has the owners sign one message that the Safe
then verifies. It moves no funds and opens no app session.

## Stopping the gate

Custody can stop the gate alone, in one transaction: **Revoke both allowances**
in the custody view sets both allowances to zero. After that every move fails at
**Execute** with a message that custody's allowance is revoked. To start again,
custody selects **Grant the allowances**, which shows the amounts and expiry
before sending.

The gate shouldn't hold anything between moves. If something is left in it, the
custody view shows it and **Return leftovers** sends it back to custody. The
Aave position belongs to custody, so custody can also withdraw it at Aave
directly, without Prime.

## Differences from Stellar

| | Stellar | EVM |
|---|---|---|
| Network | Stellar mainnet, and testnet in the beta app | Base Sepolia only |
| Account | OpenZeppelin smart account | Safe with a Zodiac Roles module |
| Custody | Custody wallet plus a gate it grants allowances to | Custody address plus a gate Safe it owns, drawing through Permit2 |
| Allowance | Per asset, for up to 180 days | Permit2 allowances for USDC and aUSDC, each with an amount and an expiry |
| Venues | Blend and Aquarius | Aave v3, and Uniswap v3 for USDC to WETH |
| Lending position held by | The Prime Account | Custody |
| Policy templates | Several, plus custom policies | Custody-funded action only |
| Two people on large moves | Set on the band | The band names a shared account |
| Swap minimum | Fixed in the rule | Set per swap from the live quote |
| Calls per batch | Up to eight | Up to two |
| Changing signers | Two transactions | One signer per transaction |
| Connected apps | Requests go through the account's rules | Message signing only |
