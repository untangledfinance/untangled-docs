# Repay and withdraw

Repay & withdraw reduces an open position. It repays part of the USDC debt, with USDC brought back from the yield source, and withdraws part of the tXAU collateral to custody. Either amount can be zero. A withdraw with nothing to repay makes no bridge transfer.

To close the whole position, use [Close](./05.close.md). If the two amounts cover everything, the button becomes **Close** and runs the same Close.

:::note
Repay & withdraw needs its own rule on the account, the repay role. See [Rules and signer B](./06.rules-and-signer-b.md#the-repay-role). If the card asks for it, select **Set up**.
:::

## The fields

The **My position** card has two tabs, **Repay & withdraw** and **Close**. The Repay & withdraw tab has two fields.

| Field | Unit | Hint | Buttons |
|---|---|---|---|
| **Repay** | USDC | `Owed (all lines) X`: the debt custody owes on Base | 25%, 50%, 75% and MAX of the repay maximum |
| **Withdraw** | tXAU | `Max X`: the most tXAU the health factor allows for the repay you typed | 25%, 50%, 75% and MAX of the withdraw maximum |

The debt is shared by both lines, so **Owed (all lines)** is the same on the Kamino and OctoLend cards.

Below the fields, a preview line shows the health factor before and after the run, in the form `Health factor before → after`. The preview uses the smallest repay the run can make.

## Limits

| Message on the field | What it means |
|---|---|
| Above what is owed | Repay can be at most the debt. MAX fills it. |
| Above 6 USDC | One run repays at most 6 USDC. Make a second run for the rest. |
| Kamino holds X, or OctoLend holds X | The yield source holds less USDC than the repay needs |
| Below 1 USDC | A run that repays must repay at least 1 USDC. Leave Repay empty to withdraw only. |
| Above your collateral | Withdraw can be at most the tXAU in the position |
| Above the daily allowance X | The withdraw is more than the allowance left. X is what is left. |
| Above the safe maximum | The health factor after the run would be below 1.5 |
| Add X USDC to custody first | Custody lacks the Circle USDC the Close reserve needs. See [Open a position](./03.open-a-position.md#check-the-review). |

**Health factor floor:** a run is refused when the health factor after it would be below 1.5. The **Withdraw** maximum is the largest amount that keeps it at 1.5.

**Daily allowance:** each line can withdraw up to 0.1 tXAU in each 24-hour period. The Kamino and OctoLend lines have separate allowances.

**Dust:** if a withdraw would leave less than 0.000001 tXAU in the position, and no debt is left, the run takes that small amount too.

**Close reserve:** the run must leave custody holding the Circle USDC the Close reserve needs.

## The button

The button label follows the amounts you typed.

| Repay | Withdraw | Button | What runs |
|---|---|---|---|
| Typed | Typed | **Repay and withdraw** | The run |
| Typed | Empty | **Repay** | The run, repay only |
| Empty | Typed | **Withdraw** | One transaction on Base, no bridge |
| The whole debt | All the collateral | **Close** | The existing Close |

Select the button to check the amounts again. The button reads **Checking…** while the app reads the chain and opens the review.

## The review

| Row | Meaning |
|---|---|
| Repay | The USDC repaid. On Kamino the row shows a range: the amount you typed, up to that amount plus the most Circle's fee can take. |
| Withdraw | The tXAU that returns to custody, or none |
| Health factor after | The health factor once the run is done |
| Fee | The most Circle's fee can take. It is 0.002 USDC at most on Kamino, and zero on OctoLend. |
| From | **Kamino** or **OctoLend** |

Select **Sign** to start the run. The review shows the figures read at the press.

## The steps

| Line | Rows |
|---|---|
| Kamino | Withdraw and send to Base · Attestation · Mint on Base · Repay and withdraw |
| OctoLend | Withdraw from OctoLend · Send to Base · Attestation · Mint on Base · Repay and withdraw |
| Withdraw only | Withdraw tXAU |

When the run repays without a withdraw, the last row reads **Repay**.

The card can stop at a row that needs you. It then offers one of these buttons:

| Button | When it shows |
|---|---|
| **Deliver** | Circle's message is not minted by itself. See [Close](./05.close.md#deliver). |
| **Repay and withdraw** | Signer B makes no progress, and your wallet can finish the Base repay |
| **Retry** | A row failed |
| **Continue** | The run is waiting for its next step |

**Abandon** appears under the run only before the burn has been sent, or after a burn that failed.

On Kamino, the Swig wallet needs a little SOL for the Circle message that the first partial repayment creates. When it is short, the card shows **Fund**. **Fund** sends it from the browser key. When the browser key cannot spare the SOL, the card shows the amount and the address to send it to instead.

If the run finished without the withdraw, the card shows **Withdraw**, which takes the remaining tXAU.

## What you sign

| Case | Wallet signature |
|---|---|
| Kamino, repay and withdraw | One signature for the Solana withdraw and send. Signer B repays on Base when it is set up. |
| Kamino, without signer B | One signature for the Solana side, and the Base repay runs from your wallet on the **Repay and withdraw** button |
| OctoLend, repay and withdraw | None for the OctoLend side. The keeper key sends it. Signer B repays on Base when it is set up, otherwise your wallet does, on the **Repay and withdraw** button. |
| Withdraw only | One signature. Signer B does not sign a withdraw alone. |

## Set up the repay role

The first time, the card shows **Set up** and the line *Repay & withdraw needs its own rule on this account: one custody signature, once.* Select **Set up**, then approve the change in custody's queue.

If custody has two or more signers, the line **Waiting for the second signer** appears after your signature. The request waits in the **Queue**, under **Waiting for other signers**. The form appears when the rule is on the account. Pressing **Set up** again does not propose the request again while it waits.
