# Set up Leverage Yield

Setup runs once for each line. Each step reads the chain first, so a step that is already done is skipped, and a page reload picks up where you stopped.

## Before you start

You need:

- A Prime Account on Base, with its signers and approval count set. See [Create a Prime Account](../06.prime-on-evm.md#1-create-a-prime-account).
- A custody gate set up by custody, with the tXAU and Circle USDC limits that custody chooses. See [Set up the custody gate](../06.prime-on-evm.md#2-set-up-the-custody-gate).
- The execution contract connected in this browser. See [Create the execution contract](../06.prime-on-evm.md#3-create-the-execution-contract).
- A little ETH on Base in your wallet for the transactions it sends. [NEEDS SOURCE: the ETH amount a new wallet needs before setup.]

The Solana and Stellar accounts are created from the setup dialog. The browser creates the keys for them.

## Open the strategy

1. Go to **Apps** and select **Leverage Yield**.
2. Select the strategy: **tXAU · Aave V4 · Kamino** or **tXAU · Aave V4 · OctoLend**.
3. Select **Rules**. If the strategy is not set up, the tab shows one line and a **Set up** button. The **My position** tab shows the same button when the card asks for it.

The setup dialog lists each step, who signs it and who pays the fees, before anything is signed. Each press runs up to the next wallet prompt. The button names the step that comes next, for example **Next: Solana account**, or **Retry: Solana account** after a failed step. A setup that is partly done shows **Continue setup**.

## Kamino: the Solana account

| Step | Who signs | What it does |
|---|---|---|
| Browser key | No prompt | Creates the key that signs the Solana steps. The key stays in this browser. |
| Fees | No prompt | Checks that the browser key holds the SOL for the steps that it pays. |
| Solana account | Your wallet | Creates the Solana account: a Swig wallet and a Squads vault. |
| Token accounts | Your wallet | Creates the token accounts the vault uses. |
| Kamino rule | Your wallet | Installs the rule that lets the browser key deposit and redeem, only on the pinned Kamino market. |
| Burn rule | Your wallet | Installs the rule that lets the browser key burn USDC to your custody on Base, and nothing else. |
| Keeper key | Your wallet | Adds this browser to the Kamino rule, when this browser is not yet a signer. |
| Open rule | Custody, 2 of 2 | Installs the Open role on the custody gate. |
| Close rule | Custody, 2 of 2 | Installs the Close role on the custody gate, with signer B as a second member. |
| Close on Solana | Your wallet | Installs the standing close rule for the Solana account. |

The step names are the ones on screen. The signer column says who approves each step. [NEEDS SOURCE: the step order and signer for the Close on Solana step, which the code installs during the first Close in some builds.]

## OctoLend: the Stellar account

| Step | Who signs | What it does |
|---|---|---|
| Stellar account | No prompt | Creates the Stellar account. This browser's keeper key deploys it and pays the fee. |
| Keeper key | Your wallet, or this browser | Creates the keeper key for this browser, when none is held. |
| Keeper rules | Your wallet, or this browser | Installs the four keeper rules: deposit and withdraw, approve, and the burn to Base. |
| Custody rules | Custody, 2 of 2 | Installs the OctoLend Open and Close roles on the custody gate, with signer B as a second member of the Close role. |

The keeper rules expire after a set period. When they do, the **Keeper rules** card asks you to renew them. [NEEDS SOURCE: the expiry period on the live app.]

## Custody signatures

Some steps change the custody gate, so custody signs them. The dialog shows **Custody · 2 of 2** (or the number of signers that custody has) in the signer column.

- The first custody signature creates a request. The line **Waiting for co-sign** appears and the request waits in the **Queue**.
- The other custody signers approve it in the **Queue**, and the step then finishes on its own. Nothing is sent twice.

## What each signature is for

| Signature | Asked of | Purpose |
|---|---|---|
| Your wallet, setup | Owner of the Prime Account | Creates Solana or Stellar accounts and their rules. These rules limit what the browser key or the keeper key may do. |
| Custody | Custody signers | Installs the Open role, the Close role and, when you add it, the repay role on the custody gate. |
| Open | Owner of the Prime Account | One transaction through the gate, opening a position. See [Open a position](./03.open-a-position.md). |
| Close and repay | Signer B, or your wallet | Repays the debt and withdraws the collateral. See [Close](./05.close.md). |

| Solana account and rules | The browser key | About 0.017 SOL, measured on 9 Nov 2026 with a new account. |
| Circle message rent for the first partial repayment | The Swig wallet | About 0.003 SOL more than the account holds at setup. The **Fund** button tops it up. |
| Stellar account and keeper rules | The keeper key, with the fee sponsor | [NEEDS SOURCE: the XLM the keeper key needs before setup.] |
