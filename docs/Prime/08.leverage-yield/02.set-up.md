# Set up Leverage Yield

Setup runs once for each line. Each step reads the chain first and skips what is already done, so a page reload picks up where you stopped.

## Before you start

You need:

- A Prime Account on Base, with its signers and approval count set. See [Create a Prime Account](../06.prime-on-evm.md#1-create-a-prime-account).
- A custody gate set up by custody, with the tXAU and Circle USDC limits that custody chooses. See [Set up the custody gate](../06.prime-on-evm.md#2-set-up-the-custody-gate).
- The execution contract connected in this browser. See [Create the execution contract](../06.prime-on-evm.md#3-create-the-execution-contract).
- Your wallet on Base Sepolia, with ETH for the transactions it sends. [NEEDS SOURCE: the ETH amount a new wallet needs before setup.]

The Solana and Stellar accounts are created from the setup dialog. The browser creates the keys for them.

## Open the strategy

1. Go to **Apps** and select **Leverage Yield**.
2. Select the strategy: **tXAU · Aave V4 · Kamino** or **tXAU · Aave V4 · OctoLend**.
3. Select **Rules**. If the strategy is not set up, the tab shows one line and a **Set up** button.

The setup dialog lists each step and who signs it, before anything is signed. Each press runs the next step. The button names that step, for example **Next: Solana account**, or **Retry: Solana account** after a failed step. It reads **Start** when no step is done yet, and **Continue setup** when a setup is partly done.

## Kamino: the Solana account

| Step | Who signs | What it does |
|---|---|---|
| Browser key | No prompt | Creates the key that signs the Solana steps. The key stays in this browser. |
| Fees | No prompt | Checks that the browser key holds the SOL for the steps it pays. The dialog shows the amount. |
| Solana account | Your wallet | Creates the Solana account: a Swig wallet and a Squads vault. |
| Token accounts | Your wallet | Creates the token accounts the vault uses. |
| Kamino rule | Your wallet | Installs the rule that lets the browser key deposit and redeem, only on the pinned Kamino market. |
| Burn rule | Your wallet | Installs the rule that lets the browser key burn USDC to your custody on Base, and nothing else. Shown when the account needs it. |
| Keeper key | Your wallet | Adds this browser's key to the Kamino rule, when this browser is not yet a signer. Shown when needed. |
| Close on Solana | Your wallet | Installs the standing close rule for the Solana account. Later Closes then make no wallet prompt on the Solana side. |
| Open | Custody | Installs the Open role on the custody gate. |
| Close | Custody | Installs the Close role on the custody gate. Signer B is added to it in the same batch when it is set up in this browser. |

If the **Close on Solana** step is not done during setup, the first Close installs the rule through its **Allow** row.

## OctoLend: the Stellar account

| Step | Who signs | What it does |
|---|---|---|
| Stellar account | No prompt | Creates the Stellar account for the line. |
| Keeper key | Your wallet | Adds this browser's keeper key when your wallet can do it. Otherwise the step says the keeper key is not in this browser. |
| Keeper rules | Your wallet, or this browser | Installs the four keeper rules: deposit and withdraw, approve, and the burn to Base. |
| Custody rules | Custody | Installs the OctoLend Open and Close roles on the custody gate. Signer B is a member of the Close role when it is set up in this browser. |
| Close | Custody | Adds signer B to the Close role when the role exists without it. The Close then needs no wallet signature. Shown only in that case. |

The keeper rules last 7 days. When they run out, use **Renew** on the **Keeper rules** card of the **Rules** tab.

## Custody signatures

Some steps change the custody gate, so custody signs them. On OctoLend the signer column shows the custody and its approval count, for example **Custody · 2 of 3**.

- The first custody signature creates a request. The line **Waiting for co-sign** appears, and the request waits in the **Queue**.
- The other custody signers approve the request in the **Queue**. The step then picks up the result from the gate.
- In the **Queue**, your request is listed under **Waiting for other signers**, with its approval count and an **Open** link to the co-sign page.

> **SCREENSHOT NEEDED:** the **Queue** with the **Waiting for other signers** section and one custody request in it. State: a connected wallet that is a signer of a custody with two or more signers, and one request that is one approval short.

## What each signature is for

| Signature | Asked of | Purpose |
|---|---|---|
| Your wallet, setup | Owner of the Prime Account | Creates the Solana or Stellar accounts and their rules. These rules limit what the browser key or the keeper key may do. |
| Custody | Custody signers | Installs the Open role, the Close role and, when you add it, the repay role on the custody gate. |
| Open | Owner of the Prime Account | One transaction through the gate, opening a position. See [Open a position](./03.open-a-position.md). |
| Close and repay | Signer B, or your wallet | Repays the debt and withdraws the collateral. See [Close](./05.close.md). |

## Costs

| Cost | Paid by |
|---|---|
| Solana account and rules | The browser key, in SOL. The setup dialog shows the amount under the **Fees** step. |
| Swig wallet for the first partial repayment | The Swig wallet holds the SOL. The **Fund** button on the Repay & withdraw tab tops it up from the browser key. |
| Stellar account deploy and keeper rules | The keeper key, in XLM. The fee sponsor does not cover the deploy. |
| Base transactions from your wallet | Your wallet, in ETH, per transaction. |

See [Fees and gas sponsorship](./08.fees-and-gas.md) for what the sponsor pays.
