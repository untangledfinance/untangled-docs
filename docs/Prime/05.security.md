# Security

Funds in a Prime setup move only under rules you set and the chain enforces.
This page covers what those rules protect, what they do not, and what to know
before you rely on them.

## What protects your funds

| Protection | What it does |
|---|---|
| Custody keeps the funds | The funds stay in your custody wallet. The gate can draw only within custody's limits, only until their expiry, and only to the addresses custody listed. Custody can lower or revoke a limit at any time. |
| The gate cannot be edited | The gate has no admin. Its destinations, time lock and recovery address are fixed when custody creates it. |
| The approval count | The account acts only when enough of its signers have approved. No single signer of a 2 of 3 account can act alone. |
| Rules | An agent acts only within the rule it sits on: the venue, the amount band and the approvals. A call outside the rule is refused on chain. |
| The time lock | A move under a rule with a wait is stored on chain first, where every signer and custody can see it, and custody or the signers can cancel it before it runs. |
| Recovery | If custody's signers lose access, the funds can reach the recovery address and no other. |
| Review from the transaction itself | What you sign, and what a co-signer sees, is decoded from the transaction and read fresh from the chain. A link or a connected app cannot show one call and carry another. |

Prime's checks sit on top of custody's own controls. Prime can refuse a move
that custody's limits would allow, but it cannot allow a move those limits
refuse.

## What a policy does not protect

These limits matter most for a delegated key.

| Limit | Why | What to do |
|---|---|---|
| A key is only as limited as the loosest rule it sits on | The caller chooses which rule authorises a call. If the key is also a signer on a rule with no policy, it can name that rule and the policy never applies. | Put a delegated key on its own rule and nowhere else. |
| A second signer on a rule with a policy does not mean two approvals | Any one signer on such a rule can act alone. | For two approvals, set the approval count on a custody-funded action band, as in [Install rules for an agent](./03.walkthrough/04.install-rules-for-an-agent.md). |
| The account's own signers are not limited by a policy | A policy limits the keys you put under it. The account's signers keep full control, which is what lets them revoke it. | Choose the account's signers and approval count with that in mind. |
| A spending limit counts ledgers, not clock time | A "per day" limit is a limit per fixed number of ledgers. Stellar closes a ledger about every five seconds, so the period is close to a day. | Size the window in ledgers. |
| A spending limit only counts transfers | It reads the amount from a call named `transfer`, and cannot see value moved by a method with another name. | Pair it with a rule that pins the method. |
| Changing the signers on a rule stops its policy working | The policy notices the change and refuses, rather than apply to a different set of people. | Install the rule again after the change. |
| How often a key acts cannot be limited | A key capped at 100 a day can still make a thousand calls of 0.1. | We [opened an issue with OpenZeppelin](https://github.com/OpenZeppelin/stellar-contracts/issues/858) about it. |

## Third-party code

Spending limits and threshold approvals use OpenZeppelin's example contracts. We
built them from OpenZeppelin's published source and deployed them ourselves. We
have not audited them, and OpenZeppelin describes that code as experimental,
provided "as is". Anything that relies on them inherits that.

The policy interpreter, which evaluates the rules you write, is ours. Its
addresses and build hash are published in the repository, so you can check the
account runs the code we say it does.

## Audit status

The OctoGate contracts have had an internal adversarial review and a threat
model. They have not had an external audit yet.

:::caution
Prime is under active development, and the flows in these docs run on Stellar
testnet. Check which network you are on before you commit real value, and start
with amounts you are prepared to lose.
:::
