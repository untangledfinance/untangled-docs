# Security

## How funds are protected

- Funds used by custody-funded actions stay in your custody wallet. The gate
  draws on them through an allowance custody can reduce or revoke at any time.
- The gate can only pay the addresses listed when it was created. It has no admin.
- The account contract checks the approval count and the agent's rules on chain.
  The app can't bypass them.
- Moves under a rule with a wait show up in the Queue first, and custody or the
  account's signers can cancel them.
- If custody loses its keys, the Prime signers can send the funds to the gate's
  recovery address.
- The co-sign page decodes the transaction itself rather than trusting the text
  sent with the link.
- A move that custody's allowance doesn't cover fails, whatever the Prime rules
  allow.

## Where policies fall short

The caller picks which rule to use. If an agent key is on two rules and one of
them has no policy, the agent can use that one. Keep delegated keys on a single
rule.

Putting two signers on a rule with a policy doesn't make both of them sign;
either can act alone. To require two people, use the approval count on a
custody-funded action band.

Policies don't restrict the account's own signers.

A spending limit's period is a number of ledgers, not hours. A ledger closes
roughly every five seconds, so "a day" is about 17,280 ledgers and can drift a
little.

A spending limit only counts calls named `transfer`. Value moved by any other
method isn't counted, so also pin the method in the policy.

If you change the signers on a rule, its policy refuses everything until you
install the rule again (see [Signers and approvals](./04.reference/01.signers-and-approvals.md)).

Nothing limits how often a key acts. A key capped at 100 a day can still make a
thousand calls of 0.1. We have
[raised this with OpenZeppelin](https://github.com/OpenZeppelin/stellar-contracts/issues/858).

## Third-party code

Spending limits and threshold approvals use OpenZeppelin's example contracts,
built from OpenZeppelin's source and deployed by us. OpenZeppelin publishes them
as experimental. Our internal review covered OctoGate, not these contracts.

The policy interpreter that evaluates your rules is our own. Its addresses and
build hash are in the repository, so you can check what the account is running.

## Audit status

OctoGate has passed our internal adversarial review and threat modelling. An
external audit is in progress.
