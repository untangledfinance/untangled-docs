# Security

## How funds are protected

- Funds used by custody-funded actions stay in your custody wallet. The gate
  draws on them through an allowance custody can reduce or revoke at any time.
- The gate can only pay the addresses listed when it was created. It has no admin.
- The account contract checks the approval count and the agent's rules on chain.
  The app can't bypass them.
- Moves under a rule with a wait show up in the Queue first, and custody or the
  account's signers can cancel them.
- If custody loses its keys, the Prime signers can send the funds to the gate's
  recovery address.
- The co-sign page decodes the transaction itself and ignores any text sent
  with the link.
- A move that custody's allowance doesn't cover fails, whatever the Prime rules
  allow.

## Setting up policies

- Keep each delegated key on a single rule. The caller picks which rule to
  use, so a key that is also on a rule without a policy can act through that
  one.
- Use the approval count to require two people. Two signers on a rule with
  a policy can each act alone; the approval count on a custody-funded action
  band makes both sign.
- Policies apply to delegated keys. The account's own signers aren't
  restricted by them.
- Spending limit periods are in ledgers. A ledger closes roughly every five
  seconds, so a day is about 17,280 ledgers.
- Pin the method as well as the amount. A spending limit counts calls named
  `transfer`.
- Reinstall a rule after changing its signers. Its policy refuses calls
  until you do (see
  [Signers and approvals](./04.reference/01.signers-and-approvals.md)).
- Spending limits cap the total, not the number of calls. We have
  [raised call-frequency limits with OpenZeppelin](https://github.com/OpenZeppelin/stellar-contracts/issues/858).

## Third-party code

Spending limits and threshold approvals use OpenZeppelin's example contracts,
built from OpenZeppelin's source and deployed by us. OpenZeppelin publishes them
as experimental. Our internal review covered OctoGate, not these contracts.

The policy interpreter that evaluates your rules is our own. Its address and
code hash are in the table below, so you can check what the account is
running.

When you set up your Prime Account, gate and execution contract, each is
created from this code and gets its own address. The app refuses a gate or
execution contract that runs any other code. Full hashes and the deployment
transactions are in the
[oz-policy-builder repository](https://github.com/untangledfinance/oz-policy-builder/blob/main/deployments/prime-mainnet.json).

The interpreter, gate and execution contract have no admin and no upgrade
function, so the wallet that uploaded their code and created the interpreter
has no control over them.
