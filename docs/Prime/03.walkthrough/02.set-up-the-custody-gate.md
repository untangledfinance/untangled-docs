# Set up the custody gate

<video controls width="100%" preload="none" poster="/img/prime/video-02-set-up-the-custody-gate.jpg" src="/video/prime/02-set-up-the-custody-gate.mp4">
  Your browser does not support the video tag.
</video>

The custody gate is the only way a Prime Account can draw on custody's funds.
Custody deploys it with its own wallet and grants it a limit per asset. The funds
stay in the custody wallet; the gate never holds them.

In the video, custody is a Stellar multisig whose other signers are Signer A and
Signer B. It sets no minimum wait, a run window of about a day, the Aquarius
XLM/USDC pool as a destination, the trustee as the recovery address, and
unlimited XLM and USDC for 180 days.

## Open the set-up

The set-up page is
[beta.untangled.finance/#/onboard/stellar/gate](https://beta.untangled.finance/#/onboard/stellar/gate).
Open it and connect the custody wallet.

A Prime signer finds the same page from the app: while the account has no gate,
**Policies** says so and links to **Set one up**, and **Manage execution** under
**Accounts** links to it too. The signer can send that link to whoever holds
custody's keys.

The set-up has four steps: **Custody**, **Destinations**, **Limit** and
**Review**.

## Custody

This step names the connected wallet as the account that holds the funds. If
that account needs more than one signature, the step says how much signing
weight it needs and how much your key carries. Every transaction in this set-up
then waits in the Queue for its other signers.

![The Custody step, showing the account that holds the funds and its signing weight](/img/prime/gate-custody.webp)

## Destinations

Paste the Prime Account this gate serves. The app works out that account's
execution contract from it: that contract is the only caller the gate answers to.

Then set the time lock for every move through this gate:

| Setting | What it means |
|---|---|
| Wait before a move runs | The least number of ledgers a move waits before it can run. 0 means no wait from the gate, so each rule sets its own. A ledger closes about every five seconds. |
| Run window | How long a move stays runnable once its wait is over. After that it lapses and never runs, because it was approved against prices that have since moved. 17,280 ledgers is about 24 hours. |

The wait applies to every move through the gate: an agent's, the Prime Account's
own, and a recovery.

![The time lock settings: wait before a move runs, and the run window](/img/prime/gate-time-lock.webp)

Next, list every venue the account will use, such as a pool. The gate refuses
any batch that names an address missing from this list. The addresses a batch
cannot avoid naming, like the Prime Account, custody and each asset, are added
for you. Anything you add can receive funds without a further approval, so add
only addresses you would be content to see paid.

Last, the **Recovery address, if any**: the one wallet custody's funds can still
reach if custody's own signers lose access, such as a trustee's wallet. Leave it
empty for a gate with no recovery path. See
[Recover custody funds](./07.recover-custody-funds.md).

![Destinations: the Aquarius pool and the recovery address](/img/prime/gate-destinations.webp)

## Limit

For each asset, set how much the gate may release and for how many days.
**Unlimited** removes the amount cap; the gate still pays only to its listed
addresses, and only until the expiry. The network keeps an allowance for at most
180 days, and **Max** stays an hour inside that. **Add another asset** adds a
second limit, such as USDC.

After the expiry, that asset can release nothing until custody grants a limit
again.

![The Limit step: unlimited, expiring in 180 days](/img/prime/gate-limits.webp)

## Review

The last step lists the gate address, the account it spends from, every address
it releases to, the limits, the time lock, and what it will refuse. The gate has
no admin, so its destinations, its time lock and its recovery address can never
change. Changing any of them means deploying a new gate.

![The Review step for the gate](/img/prime/gate-review.webp)

Select **Deploy gate and grant limits** and approve in your wallet.

## Collect custody's signatures

The set-up sends one transaction to deploy the gate and one more for each
asset's limit, three in the video. When custody's own key does not carry enough
weight, each transaction waits in the Queue:

1. Each of custody's other signers connects, opens **Transactions**, then
   **Queue**, opens the item and selects **Sign with active wallet**.
2. The item shows the weight collected so far, for example 20 of 20.
3. Once the weight is met, the last signer selects **Submit**.

![A queued gate deployment, signed by custody, waiting for its other signers](/img/prime/queue-custody-weight.webp)

When every transaction has landed, the set-up page says the gate is live and
there is nothing left to sign.

Custody can change an asset's limit later, or add an asset, with a new grant
from its own wallet. No one else is involved.
