# Recover custody funds

<video controls width="100%" preload="none" poster="/img/prime/video-07-recover-custody-funds.jpg" src="/video/prime/07-recover-custody-funds.mp4">
  Your browser does not support the video tag.

If custody's own signers ever lose access, the funds are not stuck. The Prime
Account's signers can move them, but only to the recovery address custody fixed
in the gate. Custody signs nothing.

This works only for a gate created with a recovery address. A gate without one
has no recovery path.

In the video, with custody's keys treated as lost, Signer A and the Admin move
250 XLM from custody to the trustee.

## Prepare the recovery

1. A signer of the Prime Account opens **Policies**. The custody gate card shows
   the gate, its limits, the addresses it releases to and its recovery address.
2. Select **Recover custody funds**.
3. The dialog names the recovery address and lists each asset with how much the
   gate can move now. Choose the asset and the amount. The app fills in
   everything the gate can move, less the XLM custody must keep as its reserve.
4. Select **Prepare in Prime Execution**.

![The custody gate card on Policies](/img/prime/custody-gate-card.webp)

![The Recover custody funds dialog](/img/prime/recover-dialog.webp)

## Run it

Prime Execution opens with one call: the gate pays the amount from custody to
the recovery address. It runs under the account's own authority, so it needs the
account's approval count, two of three in the video.

![Prime Execution with the recovery prepared](/img/prime/recovery-prepared.webp)

Select **Execute**, read the review, select **Run** and approve. Another signer
opens the co-sign link from the Queue. The co-sign page shows the one call: the
amount, from custody, to the recovery address. They select **Sign and continue**
and approve.

With the second approval, the recovery is on chain. Custody's keys were never
needed, and the funds could only go to the recovery address.

A recovery passes through the gate like any other move, so the gate's wait
applies to it too. In the video the gate has no wait, so it runs at once.
