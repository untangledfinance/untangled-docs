# Use the time lock

<video controls width="100%" preload="none" poster="/img/prime/video-06-execute-with-a-time-lock.jpg" src="/video/prime/06-execute-with-a-time-lock.mp4">
  Your browser does not support the video tag.
</video>

When a rule has a wait, signing a batch stores it instead of running it. The
agent can't cancel a stored move; custody and the account's signers can.

In the video the agent stores two 50 XLM swaps under the 10 to 100 XLM rule,
which has a 12-ledger wait. Custody cancels one and the other runs.

## Store a move

Build the batch in Prime Execution as described in
[Run a move](./05.run-a-move.md) and pick the rule with the wait. **Wait before
it runs (ledgers)** is set to the rule's minimum. You can set a longer wait,
not a shorter one.

Select **Execute**. The review shows that the batch will be stored and when it
can run. Select **Store** and sign.

![The review for a stored move](/img/prime/time-lock-store.webp)

## Find it in the Queue

Stored moves appear under **Transactions**, then **Queue**, labelled as delayed
moves.
Each shows **Waiting** with the ledgers left, or **Ready to run** with how long
it can still run. Open one to see its calls.

![Two delayed moves in the Queue](/img/prime/queue-delayed-moves.webp)

![An open delayed move](/img/prime/queue-delayed-move-open.webp)

## Cancel it

Custody opens the move and selects **Cancel as custody**. A signer of the Prime
Account sees **Cancel** instead. If custody is a multisig, the cancel goes to
the Queue as **Cancel a stored move from custody** and custody's other signers
sign it there; the last one selects **Submit**. The cancelled move then
disappears from the Queue.

## Run it

When the move shows **Ready to run**, any connected wallet can select **Run**
and sign. It doesn't need any new approvals. A move that isn't run within the
gate's run window lapses.
