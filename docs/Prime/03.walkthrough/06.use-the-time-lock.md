# Use the time lock

<video controls width="100%" preload="none" poster="/img/prime/video-06-execute-with-a-time-lock.jpg" src="/video/prime/06-execute-with-a-time-lock.mp4">
  Your browser does not support the video tag.
</video>

Under a rule with a minimum wait, signing a batch does not run it. The batch is
stored on chain, in public, and can run only once the wait is over. Until it
runs, custody or the account's signers can cancel it. An agent cannot.

| Stage | What happens |
|---|---|
| Wait | The stored move shows in the Queue for every signer and for custody, with when it can run. |
| Cancel | Until it runs, custody or the account's signers can cancel it. |
| Run | Once the wait is over, anyone can run it. It needs no new approval, because it was approved when it was stored. |
| Lapse | A move nobody runs within the gate's run window expires, so a stale price never executes. |

The gate fixes its own wait and run window when custody sets it up, and nobody
can shorten them later. A rule can ask for a longer wait.

In the video, the Agent stores two 50 XLM swaps under the rule for 10 to under
100 XLM, which waits 12 ledgers. Custody cancels the second, and the first runs.

## Store a move

Build the batch in Prime Execution as in [Run a move](./05.run-a-move.md), and
choose the rule with the wait under **Authorised by**. **Wait before it runs
(ledgers)** starts at the rule's minimum, 12 ledgers here, about a minute. You
can set a longer wait.

Select **Execute**. The review says it plainly: signing stores this batch on
chain, it does not run now, it can run after the wait, and until it runs the
account or custody can cancel it. Select **Store** and approve in your wallet.

![Review before you sign, for a stored move](/img/prime/time-lock-store.webp)

## Watch it in the Queue

Open **Transactions**, then **Queue**. Each stored move shows as a delayed move
with its calls and its state: **Waiting**, with how many ledgers are left, or
**Ready to run**, with how long it stays runnable.

![Two delayed moves, one waiting and one ready](/img/prime/queue-delayed-moves.webp)

Open a move to see its calls, the ledgers in which it can run, and who can act on
it. Custody sees **Cancel as custody**; the account's signers see **Cancel**.

![An open delayed move, with Run and Cancel as custody](/img/prime/queue-delayed-move-open.webp)

## Cancel a move

Custody connects, opens the move in the Queue and selects **Cancel as custody**.
If custody is a multisig, its key alone does not carry enough weight, so the
cancel waits in the Queue as **Cancel a stored move from custody**. Custody's
other signers each select **Sign with active wallet**, and the last one selects
**Submit**.

The cancelled move leaves the Queue. The money never left custody.

## Run a move

When the wait is over, the move reads **Ready to run**. Anyone can select **Run**
and approve. The XLM is swapped and the USDC goes back to custody, as in any
other move.
