# Run a move

  Your browser does not support the video tag.

This page covers moves under rules with no minimum wait. For rules with a wait,
see [Use the time lock](./06.use-the-time-lock.md).

In the video, the Agent works under the three rules from the previous step:

| The Agent tries | Under the rule | What happens |
|---|---|---|
| Swap 5 XLM for USDC | Under 10 XLM, Agent alone | Runs at once, and the USDC goes back to custody |
| Swap 50 XLM | Under 10 XLM, Agent alone | The account refuses it on chain. Nothing is signed and nothing moves. |
| Swap 150 XLM | 100 XLM and up, Agent and Admin | Runs once the Admin co-signs |

## Open Prime Execution

The Agent connects its wallet, picks the Prime Account from the **Prime
Account** button at the top of the page, and opens **Apps**, then **Prime
Execution**. An agent that drives the app in a browser can connect with Stellar
Wallet, the wallet built into the app, in place of a browser extension. Read the
caution on [Stellar Wallet](../04.reference/04.apps-accounts-and-portfolio.md#stellar-wallet)
first.

Under **Authorised by**, choose the rule to act under. A signer of the account
can also choose **This account's own authority**, which needs the account's own
approval count.

## Build the batch

A batch holds up to eight contract calls and runs as one transaction. Enter each
call as a card in the **Interactive** view, or edit the whole batch as text in
the **Raw** view. Both views show the same batch.

A swap of custody's XLM on Aquarius takes three calls:

| Call | What it does |
|---|---|
| 1 | The custody gate pulls the XLM from custody |
| 2 | The Aquarius pool swaps it, with the least USDC you will accept |
| 3 | The USDC is transferred back to custody |

![Prime Execution with the three calls of a swap](/img/prime/prime-execution-calls.webp)

A batch cannot call the Prime Account, its interpreter or the execution contract
itself, so a batch can never change what the account is allowed to do.

Leave **Wait before it runs (ledgers)** at 0 for a rule with no minimum wait.

## Check, review and run

Select **Execute**. The app checks the batch against the account first, then
opens **Review before you sign** with what the account would authorise and the
estimated fee. Nothing is signed yet. Select **Run** and approve in your wallet.

When it lands, the app shows **Done**, with a link to the transaction. The swap
and the return to custody happened in that one transaction.

![The batch ran](/img/prime/prime-execution-done.webp)

## When the batch is outside the rule

If the batch breaks the rule, the app says so before you sign. For example: Rule
2 covers under 10 XLM, this batch draws 50 XLM, and the account will refuse it
under that rule.

![The warning shown before signing](/img/prime/prime-execution-warning.webp)

If you run it anyway, the account itself refuses it while the transaction is
being simulated. The app shows **Refused**, with the rule that refused it.
Nothing was signed and nothing moved. The refusal comes from the account on
chain, so the app cannot override it.

![The account refused the batch](/img/prime/prime-execution-refused.webp)

## When the rule needs a second approval

A rule with two approvals, such as the Agent and the Admin, works like any
shared approval. After the Agent signs, the app shows **More signatures needed**
and saves the request in the Queue. The Admin connects, opens **Transactions**,
then **Queue**, opens the co-sign link and checks each call: what is pulled,
swapped and paid back. They select **Sign and continue** and approve, and the
swap goes through.
